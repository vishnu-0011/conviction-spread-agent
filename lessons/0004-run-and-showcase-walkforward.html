ConvictionSpread · Lesson 4 · 10 minutes

Run it. Prove it. Describe it honestly.

Create two clean pieces of evidence for LinkedIn: one showing that the software is tested, and one showing that the research pipeline runs.

Tangible win: leave this lesson with two safe screenshots that demonstrate engineering progress without presenting synthetic results as real Alpaca paper-trading performance.

1. Open the project in PowerShell

cd C:\Project\alpaca-hackathon
git branch --show-current
git status --short --branch

The branch should be main. The status should show main...origin/main with no modified files.

2. Run all automated tests

$env:PYTHONPATH = "src"
python -m unittest discover -s tests -v

Let the command finish, then capture the final lines:

Ran 35 tests

OK

This is the strongest first screenshot. It proves the data parser, feature engine, risk rules, order payloads, simulation, and walk-forward integration all pass their current automated checks.

3. Run the fixture-backed simulation

python scripts/run_simulation.py

The command prints the complete JSON report. It compares four strategies across train, validation, and test folds and reports P&L, drawdown, win rate, payoff ratio, profit factor, rejection rate, and P&L per unit of risk.

4. Print a screenshot-sized summary

After the simulation completes, paste this block into the same PowerShell window:

$report = Get-Content "docs/evidence/phase-3-walkforward-report.json" -Raw | ConvertFrom-Json
$agent = $report.strategies | Where-Object { $_.name -eq "conviction_spread" }

[pscustomobject]@{
  Evidence            = "Synthetic fixture - not Alpaca paper P&L"
  Result              = $report.label
  BeatsBaselines      = $report.beats_baselines
  WalkForward         = "train / validation / test"
  StrategiesCompared  = $report.strategies.Count
  TestTrades          = $agent.test.trade_count
  TestNetPnL          = $agent.test.net_pnl
  TestMaxDrawdown     = $agent.test.max_drawdown
} | Format-List

The current archived report should produce a compact summary resembling:

Evidence            : Synthetic fixture - not Alpaca paper P&L
Result              : validated
BeatsBaselines      : True
WalkForward         : train / validation / test
StrategiesCompared  : 4
TestTrades          : 2
TestNetPnL          : 258.40
TestMaxDrawdown     : 0.00
Interpretation: validated means the code completed its internal fixture comparison. The current fixture is a small, mostly rising SPY series with synthetic option quotes. These values are not paper account P&L and are not evidence of future profitability.

What to put in the LinkedIn carousel

  1. Screenshot 1: the bottom of the test run showing Ran 35 tests and OK.
  2. Screenshot 2: the compact simulation summary, keeping its synthetic-fixture disclaimer visible.
  3. Optional screenshot 3: the GitHub README progress table or the archived JSON evidence file.

Never include these in a screenshot

  • The local .env file
  • Alpaca API keys or secret keys
  • An unmasked account ID or account number
  • A cropped 100% win rate without the fixture limitation

Retrieval check

What do the 35 passing tests prove?

They prove the implemented behaviors match the current automated specifications; they do not prove the trading strategy will be profitable.

Why must the synthetic-fixture label remain visible?

Because the option quotes and outcomes are simplified research inputs, not fills or P&L produced by the Alpaca paper account.

Primary reading

Alpaca's Paper Trading documentation explains why even broker-simulated results differ from live execution. Our current fixture simulation is an earlier research stage still.
