Create paper API keys safely

Generate credentials for a development paper account, store them locally, and verify that Git cannot see the secret file.

Tangible win: a local .env containing paper credentials, ignored by Git and ready for the GET-only preflight.

1 · Create or enter the paper account

  1. Open Alpaca login.
  2. If new, choose sign up, enter your email/password, confirm the verification email, and activate MFA when prompted.
  3. After login, open the account selector in the upper-left corner.
  4. Select Paper Trading. Do not select a live account.

Use this as the development account. The hackathon's fresh judging account is created only after the agent is stable.

2 · Generate the credential pair

  1. From the selected paper account, open Home or the API section.
  2. Find the card labeled API Keys or Trading API Keys.
  3. Click Generate New Key / Generate API Keys.
  4. Copy the displayed API Key ID.
  5. Copy the displayed Secret Key before closing the dialog.
The secret is one-time-visible. If it is lost, generate a new pair. Alpaca invalidates the old pair, so every integration using it must then be updated.

3 · Store them locally

From C:\Project\alpaca-hackathon:

Copy-Item .env.example .env

Open .env in your editor. Replace only the empty values:

ALPACA_API_KEY=PASTE_THE_API_KEY_ID_HERE
ALPACA_SECRET_KEY=PASTE_THE_SECRET_KEY_HERE
ALPACA_PAPER=true

CSA_EXECUTION_ENABLED=false
CSA_DRY_RUN=true

Do not add quotation marks, spaces around =, or a second copy of either variable. Save the file.

4 · Prove Git ignores it

git check-ignore .env

The expected output is exactly .env. Then run:

git status --short

The secret file must not appear in the status output.

5 · Run the safe connectivity check

python scripts/preflight.py --underlying SPY `
  --output data/private/preflight.json

This makes GET requests only and prints masked identifiers. A 401 normally means the key and secret are mismatched, regenerated, or belong to a different environment.

Retrieval check

Which account should generate these first keys?

A development paper account, not a live account and not the fresh judging account.

What must you do before closing the key dialog?

Copy the Secret Key because Alpaca displays it only once.

What proves the credentials are not staged for Git?

git check-ignore .env outputs .env, while git status --short does not list it.
